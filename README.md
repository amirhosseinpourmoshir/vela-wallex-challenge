# وِلا | Vela

پنل فارسی پایش و اجرای معاملات **اسپات تومانی والکس** با موتور محلی مستقل از LLM، مسیر مدل، مخزن دانش افزایشی و بک‌تست تاریخی.

Node.js 24، Express، React/TypeScript، Tailwind و SQLite؛ یک فرایند، بدون Docker و میکروسرویس.

[English](README.en.md) · [مستندات](docs/README.md) · [شروع سریع](docs/quickstart.md) · [معماری](docs/architecture.md)

![نشان اختصاصی وِلا](public/vela-whale.png)

## قابلیت‌ها

| بخش | رفتار فعلی |
| --- | --- |
| بازار | کشف بازارهای مجاز حساب، قیمت WebSocket و پشتیبان REST، نشان تازگی |
| دانش | تاریخچهٔ رسمی OHLCV، دریافت افزایشی، حذف تکرار، اسناد و embedding اختیاری |
| محلی | رتبه‌بندی چندافقی، هزینه و اندازه‌گذاری ریسک، بدون فراخوانی LLM |
| مدل | پیشنهاد ساختاریافته، نظارت بر سیگنال یا انتخاب رتبه‌بندی‌شده |
| سفارش | تأیید هر سفارش یا مجوز محدود جلسه، ثبت پاسخ و تطبیق وضعیت |
| بک‌تست | بازپخش تاریخی، سرمایهٔ شبیه‌سازی مستقل، منحنی سرمایه، توقف و حذف نتایج |
| رابط | فارسی و RTL، تم روشن/تیره، تاریخ شمسی، نمودار زنده و هشدار پیشنهاد |

**سیاست چالش: فقط اسپات، بدون اهرم و فروش بدون دارایی.** دامنهٔ رابط TMN است. [۳۴۵ جفت‌ارز مسدود](config/challenge-markets.js) با محدودیت‌های طرح و تنظیمات محلی ترکیب می‌شوند. تعداد مجاز از همگام‌سازی به دست می‌آید و ثابت نیست.

## اجرا

Node.js **24.18+ از شاخهٔ 24** و npm لازم است؛ SQLite داخلی Node استفاده می‌شود.

```powershell
git clone https://github.com/amirhosseinpourmoshir/vela-wallex-challenge.git
cd vela-wallex-challenge
npm ci
Copy-Item .env.example .env
npm run dev
```

پنل: **http://localhost:3000**. برای اتصال حساب، فایل محلی را مطابق [تنظیمات](docs/environment.md) کامل کنید:

```powershell
npm run env:check
npm run markets:sync
npm run dev
```

فایل موجود `.env` را با قالب بازنویسی نکنید. `markets:sync` اطلاعات حساب/بازار را می‌خواند و فهرست محلی و بعضی تنظیمات را به‌روز می‌کند؛ سفارش نمی‌فرستد. سرور روشن را پس از تغییر تنظیمات بازراه‌اندازی کنید. `env:check` بررسی عمومی است و همهٔ موارد آن برای موتور محلی لازم نیستند.

## محلی بدون مدل

در «آماده‌سازی دانش»، تاریخچهٔ ارزهای منتخب را دریافت و مشارکت آن‌ها را فعال کنید. سپس در «ایجنت ← حساب و اجرای واقعی»، حالت سریع، «انتخاب بهترین بازار» و **«دیده‌بان محلی · بدون مدل»** را انتخاب کنید؛ سرمایه، ریسک و روش مجوز جلسه را مشخص و شروع کنید.

موتور `local-multiframe-v1` شواهد قیمت/حجم، روند، هزینه، اندازه و نقدشوندگی را در بازبینی دقیقه‌ای می‌سنجد. رتبهٔ اول الزام به خرید نیست. مصرف توکن تصمیم محلی صفر است؛ embedding یا بک‌تست مدل، اگر جداگانه اجرا شوند، سرویس خودشان را استفاده می‌کنند.

[الگوریتم](docs/local-trading.md) · [چرخهٔ سفارش](docs/reviewed-live-orders.md)

## اجرای سفارش و حدود قابلیت

موتور محلی `LIMIT` در مظنهٔ لحظه‌ای می‌سازد. مسیر مدل می‌تواند `MARKET` بخواهد؛ اگر والکس `isMarketTypeEnable=false` اعلام کند، پیش از ارسال سفارش محدود جایگزین می‌شود. پرشدن محدود تضمین نیست؛ در جلسهٔ خودکار معتبر، باقیماندهٔ سفارش سریع پس از ۱۲۰ ثانیه برای لغو ارسال می‌شود.

حد ضرر/سود اسپات توسط سرور و جلسهٔ فعال پایش می‌شود؛ سفارش حفاظتی بومی صرافی نیست. **قطع پایش یا سرور، موقعیت صرافی را نمی‌بندد.** بستن مرورگر سرور را متوقف نمی‌کند. پاسخ نامعلوم سفارش بدون تطبیق تکرار نمی‌شود.

تاریخچه از والکس با واحد تومان است؛ شکاف داده ساخته نمی‌شود. embedding بازیابی است، نه آموزش وزن مدل. بک‌تست سرمایهٔ مستقل پنج‌میلیونی و افق یک دقیقه تا ۳۰ روز دارد؛ سفارش صرافی نمی‌فرستد و اجرای واقعی/صف سفارش را دقیق بازسازی نمی‌کند. [بک‌تست](docs/agent-engine.md)

## تست و build

```powershell
npm test
npm run check
npm run build
$env:NODE_ENV='production'
npm start
```

تست‌ها از مدل/صرافی جعلی استفاده می‌کنند؛ کلید خصوصی و سفارش واقعی لازم ندارند. سرور production هم روی loopback است و احراز هویت انتشار اینترنتی ندارد.
