# Vela / وِلا

پنل محلی چالش والکس — اسکلت اولیه، بدون ایجنت و بدون ارسال سفارش واقعی.

## اجرا

Node.js 24.18 یا جدیدتر (شاخهٔ 24 LTS) لازم است. SQLite داخلی Node استفاده می‌شود؛ دیتابیس جداگانه لازم نیست.

```powershell
npm install
npm run dev
```

آدرس: http://localhost:3000

## بررسی و اجرای production

```powershell
npm run check
npm run build
$env:NODE_ENV='production'
npm start
```

سرور فقط روی 127.0.0.1 گوش می‌دهد. انتشار عمومی نیازمند احراز هویت و پیکربندی جداگانه است. فایل .env در شروع سرور به‌صورت محلی بارگذاری می‌شود؛ فایل .env.example قالب بدون کلید است. راهنمای کامل: [تنظیمات محیط](docs/environment.md).

## ساختار

- `server.js`: Express، Vite middleware در توسعه، SQLite و WebSocket روی همان پورت.
- `src/main.tsx`: پنل فارسی React، نمودار، جست‌وجوی بازار، تب‌ها، خروجی JSON و کنترل پیش‌نمایش.
- `src/style.css`: Tailwind CSS 4 و طراحی اختصاصی واکنش‌گرا.
- `public/logo.svg`: نشان اختصاصی Vela؛ لوگوی رسمی والکس نیست.
- `public/chart-icon.svg`: تصویر برداری ایزومتریک نمودار با عمق سه‌بعدی.
- `data/vela.sqlite`: هنگام اجرا ساخته می‌شود و در Git قرار نمی‌گیرد.

## وضعیت واقعی امکانات

تمام قیمت‌ها، معاملات، دلایل و نمودارها ساختگی و صرفاً برای نمایش رابط‌اند. بازه‌ها دادهٔ نمایشی را تغییر می‌دهند؛ بازده حساب واقعی نیست. دکمهٔ شروع فقط وضعیت پیش‌نمایش را در SQLite ذخیره می‌کند. WebSocket فقط اتصال محلی و heartbeat دارد. تنها تنظیمات پیش‌نمایش در SQLite ذخیره می‌شود؛ مخزن دادهٔ بازار هنوز ساخته نشده است.

اتصال معاملاتی والکس، ایجنت LLM، مدیریت ریسک، اجرای سفارش و بک‌تست هنوز پیاده‌سازی نشده‌اند. بخش «تست سرویس‌ها» اتصال واقعی خواندنی والکس و تولید یک پاسخ کوتاه از مدل را بررسی می‌کند؛ موفقیت تست به معنی آماده بودن موتور معاملات نیست. گزارش JSON داشبورد نیز برچسب demo دارد.

فونت Peyda با وزن‌های محلی از public/fonts/peyda بارگذاری می‌شود؛ اتصال به سرویس فونت خارجی لازم نیست. فایل‌ها از پروژهٔ torob_challenge کپی شده‌اند. نشان اصلی جدید، وال سه‌بعدی با پس‌زمینهٔ شفاف، در public/vela-whale.png قرار دارد؛ با ابزار داخلی imagegen ساخته شده است. فایل‌های SVG قبلی فقط به‌عنوان نسخهٔ آرشیوی باقی مانده‌اند.

## API محلی

- `GET /api/status`: وضعیت زیرساخت و پیش‌نمایش
- `POST /api/pause`: بدنهٔ JSON شامل `paused` از نوع boolean
- `/ws`: وضعیت اتصال و heartbeat؛ فاقد دادهٔ زندهٔ بازار
- `GET /api/services`: وضعیت تنظیم بودن سرویس‌ها بدون کلیدها
- `POST /api/services/wallex/test`: تست خواندنی کلید با دریافت کارمزد حساب
- `POST /api/services/llm/test`: تست BoxAPI با پیام ثابت، سقف ۶۴ توکن خروجی و بدون retry خودکار

در بخش «تست سرویس‌ها»، هر تست فقط با کلیک انجام می‌شود. تست مدل ممکن است هزینهٔ اندکی داشته باشد. درخواست‌ها از سمت سرور هستند؛ هیچ کلیدی به مرورگر برنمی‌گردد و پاسخ خام سرویس‌ها هم نمایش داده نمی‌شود. محدودیت محلی هر سرویس یک تست در ۱۰ ثانیه و یک درخواست هم‌زمان است. نتایج در حافظهٔ صفحه‌اند و با خروج از صفحه پاک می‌شوند. این بخش برای اجرای محلی است و احراز هویت پنل عمومی ندارد.

```powershell
npm run test:services
```

معماری یک برنامهٔ واحد است؛ بدون Docker یا میکروسرویس. هیچ API key در این نسخه لازم نیست.

## بازارهای طرح چالش

```powershell
npm run markets:sync
npm run test:markets
```

همگام‌سازی با کلید والکس موجود در `.env` انجام می‌شود و فقط بازارهای اسپات خارج از فهرست ممنوع طرح چالش را در SQLite نگه می‌دارد. فهرست حساب و طرح از API کشف و با نام دقیق تطبیق داده می‌شود؛ ابهام مجوز حساب در پنل نمایش داده می‌شود. تب «بازارها» فهرست نمونهٔ قبلی را با اسنپ‌شات واقعی این جدول جایگزین کرده است. این فرمان کلید یا مجوز معامله ایجاد نمی‌کند و موتور همچنان خاموش است.

[یافته‌ها و انتخاب منبع داده](docs/market-data-sources.md)

## بررسی تنظیمات

```powershell
npm run env:check
npm run test:config
```

این بررسی‌ها هیچ درخواست والکس یا LLM ارسال نمی‌کنند. تنظیمات ایجنت و ریسک برای مرحلهٔ بعد آماده شده‌اند؛ موتور هنوز پیاده‌سازی نشده است.
