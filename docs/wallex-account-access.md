# بررسی دسترسی حساب والکس — ۳۰ مهر ۱۴۰۵

همهٔ درخواست‌ها فقط GET بوده‌اند. کلید و شناسهٔ خصوصی در این گزارش درج نشده‌اند.

| مسیر | پاسخ | مشاهده |
|---|---|---|
| /sub-accounts | 200 | حساب اعتباری چالش مطابق تنظیمات؛ isActive=true و isSuspend=false |
| /v1/account/fee | 200 | کلید API پذیرفته شد |
| /v1/account/balances-detail با هدر حساب | 200 | موجودی قابل دسترس تومانی ۵ میلیون |
| /margin-trade/v1/positions با هدر حساب | 200 | درخواست خواندن موقعیت‌ها پذیرفته شد |
| /v1/prop/user/packages/active با هدر حساب | 401 | success=false، code=1201، «ابتدا وارد شوید» |
| همان مسیر بدون هدر حساب | 401 | همان پیام و کد |

[Swagger رسمی اعتبار](https://developers.wallex.ir/assets/files/trade-credit-ff5c60b5b97b77a5b2c2e4800f07729c.yaml) برای مسیر active از x-api-key و هدر Sub-Account-Client-id نام می‌برد. درخواست مطابق این قرارداد ارسال شد.

نتیجهٔ قطعی: حساب فعال است و کلید برای چند مسیر معتبر است؛ endpoint جزئیات طرح با این کلید قابل دسترس نیست. علت نهایی این اختلاف از پاسخ 401 معلوم نمی‌شود و باید سمت والکس بررسی شود؛ محدودیت endpoint/مجوز یا ناسازگاری سرویس احتمال است، نه تشخیص قطعی. فعال‌بودن حساب یا موفقیت GET، مجوز ارسال سفارش را اثبات نمی‌کند.

متن قابل ارسال به پشتیبانی: «با همان x-api-key، sub-accounts، account/fee، balances-detail و margin positions پاسخ 200 می‌دهند؛ حساب prop فعال و تعلیق‌نشده است و شناسهٔ حساب تطبیق دارد. GET /v1/prop/user/packages/active با هدر Sub-Account-Client-id پاسخ 401، code=1201 و پیام ابتدا وارد شوید می‌دهد. بدون هدر نیز همین پاسخ دیده می‌شود. لطفاً پشتیبانی احراز هویت API key و دسترسی این endpoint برای حساب چالش را بررسی کنید.»

## بررسی تکمیلی امکان معامله

خواندن /margin-trade/v1/positions با کلید حساب پاسخ 200 و فهرست خالی داد. مسیرهای overview و history حساب مانند active پاسخ 401/code1201 دادند. این اختلاف، مسدودبودن سفارش را اثبات نمی‌کند؛ مجوز نوشتن از موفقیت GET نتیجه نمی‌شود.

طبق مستندات، POST /margin-trade/v1/positions مسیر مستقل ایجاد موقعیت است و شناسهٔ خروجی active را در بدنه لازم ندارد. هیچ درخواستی به این مسیر برای ثبت سفارش فرستاده نشد.

محاسبهٔ عمومی POST /margin-trade/v1/public/loan برای BTCTMN، ADATMN، USDTTMN و XAUTTMN با ضریب ۲، حداقل وثیقهٔ ۱٬۵۰۰٬۰۰۰ و حداکثر ۵۰٬۰۰۰٬۰۰۰ تومان برگرداند. dry-run عمومی BTC با وثیقهٔ ۱٬۵۰۰٬۰۰۰ پاسخ 200/success=true داد. این‌ها محاسبهٔ بدون معامله و بدون احراز هویت بودند؛ اجازهٔ سفارش حساب چالش را تأیید نمی‌کنند. این حدود برای ضریب بررسی‌شده‌اند و باید در زمان سفارش و برای ضریب انتخابی دوباره دریافت شوند.

سقف وثیقهٔ هر ارز در شبیه‌ساز حداکثر ۲۳٫۵٪ سرمایه است؛ برای ۵ میلیون، ۱٬۱۷۵٬۰۰۰ تومان. بنابراین سفارش تعهدی با ضریب ۲ و این سقف، حداقل عمومی بررسی‌شده را رعایت نمی‌کند. پیش از توسعهٔ اجرای واقعی، اندازه‌گذاری باید حداقل‌های واقعی را بشناسد؛ افزایش خودکار سقف ریسک یا وانمودکردن اجرای سفارش مجاز نیست.
