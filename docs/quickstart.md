# نصب و اولین اجرا

Node.js 24.18+ از شاخهٔ 24، npm، Git و دسترسی شبکه به سرویس‌های انتخابی لازم است. SQLite داخلی Node است. بنچمارک سخت‌افزار عمومی منتشر نشده است.

## Windows / PowerShell

```powershell
git clone https://github.com/amirhosseinpourmoshir/vela-wallex-challenge.git
cd vela-wallex-challenge
npm ci
Copy-Item .env.example .env
npm run dev
```

در Linux/macOS از `cp .env.example .env` استفاده کنید. فایل `.env` موجود را با قالب بازنویسی نکنید. متغیر محیط سیستم بر فایل اولویت دارد.

## اتصال

۱. مقادیر اختصاصی را طبق [environment.md](environment.md) در `.env` وارد کنید.
۲. کلید مخصوص حساب چالش با مجوز خواندن/معامله تهیه کنید؛ برنامه برداشت/انتقال ندارد.
۳. `npm run markets:sync` را اجرا کنید. حساب/طرح باید دقیق تطبیق داشته باشند. این فرمان فهرست و بعضی تنظیمات محلی را به‌روز می‌کند، نه سفارش صرافی.
۴. سرور را با `npm run dev` دوباره اجرا و http://localhost:3000 را باز کنید.
۵. در «آماده‌سازی دانش»، تاریخچهٔ ارز منتخب را دریافت و مشارکت آن را فعال کنید. embedding برای موتور محلی لازم نیست.

`env:check` حضور/قالب تنظیمات را بررسی می‌کند، نه اعتبار کلید. فهرست عمومی آن شامل پیش‌نیاز مدل و تنظیمات قدیمی هم هست.

## موتور و مجوز

- محلی: معاملهٔ سریع → انتخاب بهترین بازار → دیده‌بان محلی · بدون مدل.
- مدل: Chat Completions سازگار و مدل در دسترس ارائه‌دهنده لازم است؛ سهمیه و هزینهٔ سرویس برقرار است.
- بک‌تست: مدل جداگانه استفاده می‌شود؛ سرمایه شبیه‌سازی است و سفارش صرافی ارسال نمی‌شود.

`LIVE_ORDER_REVIEW_ENABLED=true` قابلیت سفارش سرور را فعال می‌کند. سپس تأیید هر سفارش یا مجوز محدود خودکار همان جلسه را در رابط انتخاب کنید. انتخاب ارز یا متغیر محیط به‌تنهایی مجوز نامحدود نیست.

## build

```powershell
npm test
npm run check
npm run build
$env:NODE_ENV='production'
npm start
```

برای توسعه در همان پوسته: `$env:NODE_ENV='development'`. فقط یک سرور روی پورت انتخابی اجرا کنید. تغییر سمت سرور به restart نیاز دارد؛ رابط ممکن است با Vite به‌روز شود.
