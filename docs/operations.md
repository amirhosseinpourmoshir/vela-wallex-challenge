# عملیات، پشتیبان و عیب‌یابی

## چرخهٔ اجرا

`npm run dev` برای توسعه، و `npm run build` سپس `NODE_ENV=production npm start` برای خروجی ساخته‌شده است. نمونهٔ PowerShell در [شروع سریع](quickstart.md) است. سرور فقط loopback است. عمومی‌شدن مخزن GitHub هیچ پورت برنامه‌ای را باز نمی‌کند.

بستن tab، scheduler سرور را متوقف نمی‌کند. قطع پایش یا توقف سرور، سفارش صرافی را خودکار نمی‌بندد. جلسهٔ watching ذخیره‌شده ممکن است پس از restart ادامه بدهد. قبل از ارتقا/خاموشی، سفارش‌های باز و حفاظت موجود را در صرافی بررسی کنید.

## پشتیبان

پس از توقف کامل سرور و بررسی مواجههٔ حساب، نمونهٔ مسیر پیش‌فرض:

```powershell
$backupPath = Join-Path $env:USERPROFILE 'VelaBackups'
New-Item -ItemType Directory -Force -Path $backupPath
Copy-Item -LiteralPath '.\data\vela.sqlite' -Destination (Join-Path $backupPath 'vela.sqlite')
```

اگر SQLITE_PATH فرق دارد، مسیر واقعی را استفاده کنید. backup را در repo یا محل عمومی نگذارید. `.env` را جداگانه و خصوصی نگه دارید. برای restore، سرور باید خاموش و نسخهٔ دیتابیس با کد سازگار باشد؛ فایل فعلی را قبل از جایگزینی حفظ کنید. این راهنما دستور حذف تاریخچه یا پاک‌کردن سفارش نامعلوم نمی‌دهد.

## خطاهای متداول

| نشانه | معنی / اقدام |
| --- | --- |
| EADDRINUSE | فرایند دیگری روی پورت است؛ سرور مربوط به همین پروژه را پیدا و عادی متوقف کنید، همهٔ Nodeها را نکشید |
| SQLite/Node نامعتبر | نسخهٔ Node را با `node --version` بررسی و شاخهٔ 24.18+ استفاده کنید |
| کلید یا طرح تأیید نشد | حساب/طرح/انقضا و مجوز کلید را بررسی کنید؛ موفقیت GET اجازهٔ سفارش را ثابت نمی‌کند |
| کندل تازه کافی نیست | تاریخچهٔ مجاز را همگام کنید؛ شکاف/پاسخ بدون داده ممکن است واقعی باشد |
| محلی معامله نمی‌کند | مانع هر بازار را بخوانید؛ نبود بازیابی، حجم، اقتصاد خالص یا حداقل اندازه دلیل معتبر است |
| رتبه‌بندی کامل در پاسخ مدل نیست | schema مدل ناقص است؛ خطای برنامه پیش از ارسال، نه رد صرافی |
| Wallex 422، MARKET مجاز نیست | متادیتای بازار و نسخهٔ routing را بررسی کنید؛ نسخهٔ فعلی در صورت false بودن قابلیت، LIMIT می‌سازد |
| spread/ریسک/حداقل سفارش | quote اجرایی از حدود خارج است؛ افزایش خودکار بودجه برای گذراندن حداقل انجام ندهید |
| پاسخ شبکه نامعلوم / unknown | ممکن است سفارش پذیرفته شده باشد؛ تطبیق client_id و پنل صرافی، نه retry |
| سفارش accepted و مقدار اجرا صفر | هنوز fill رخ نداده؛ از رشد قیمت این سفارش سودی ایجاد نشده است |
| حد ضرر روی کارت هست اما حفاظت خاموش | صرف ذخیرهٔ عدد، سفارش حفاظتی بومی نیست؛ سرور/جلسه/مجوز را بررسی کنید |
| اجرای محلی و توکن غیرصفر | engine همان جلسه و منبع فراخوانی را ببینید؛ بک‌تست/embedding مستقل را با live local قاطی نکنید |
| قیمت UI قدیمی | اتصال عمومی/REST و نشان stale را بررسی کنید؛ نمودار قدیمی را مظنهٔ تازه فرض نکنید |

## نگهداری و هزینه

برای تغییر موتور یا حدود، جلسهٔ تازه با تأیید مستقل بسازید. مجوز مصرف‌شده با بستن معامله خودکار شارژ مجدد نمی‌شود. job دانش و embedding از تصمیم معامله جداست. سقف صفر توکن فقط سقف اختیاری برنامه را حذف می‌کند؛ سهمیه و هزینهٔ ارائه‌دهنده باقی است.

برای تغییرات: backup، خواندن CHANGELOG، نصب با npm ci، تست و build. تغییر schema مستقیم و پاک‌کردن live_orders راه‌حل خطای اجرا نیست.
