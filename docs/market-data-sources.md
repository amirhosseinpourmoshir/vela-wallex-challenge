> آرشیو توسعه؛ سیاست فعلی فقط اسپات تومانی و بدون اهرم است. اعداد/مجوزهای این گزارش وضعیت جاری حساب یا توصیهٔ معاملاتی نیستند. [راهنمای فعلی](README.md).

> فهرست‌ها و شمار بازارهای متن زیر snapshot قدیمی‌اند؛ از markets:sync و محدودیت‌های فعلی استفاده کنید.

# بازارهای طرح چالش و انتخاب منبع داده

## نتیجهٔ کشف از API

در ۲۰۲۶-۱۰-۲۲، API حساب یک حساب اعتباری فعال و تعلیق‌نشده با عنوان «هکاتون استارکوچ | والکس» نشان داد. طرح فعال عمومی با همین عنوان دقیق و یکتا، شناسهٔ **۱۸۳** داشت.

مسیر بررسی:

1. `GET /sub-accounts` برای شناسایی حساب چالش.
2. `GET /v1/prop/user/packages/active` با هدر مستند `Sub-Account-Client-id` آزمایش شد اما HTTP 401 برگرداند.
3. `GET /v1/prop/packages` برای تطبیق دقیق و یکتای عنوان طرح فعال با عنوان حساب.
4. `GET /v1/prop/packages/183` برای دریافت `unavailableMarkets`.
5. `GET /hector/web/v1/markets` برای متادیتای بازارها.

فیلتر: `is_spot === true` و نبودن نماد در `unavailableMarkets` طرح و `TRADING_BLOCKED_SYMBOLS` محلی، با پایهٔ TMN یا USDT.

در اسنپ‌شات اولیه از ۴۶۹ بازار عمومی، **۱۲۰ بازار** باقی ماند: **۶۲ تومانی و ۵۸ تتری**. این عدد وضعیت زمان واکشی است؛ مقدار جاری را با فرمان زیر از نو بگیرید:

```powershell
npm run markets:sync
```

اسکریپت فقط GET می‌زند. بازار غیرمجاز، غیر اسپات یا اسنپ‌شات ساختگی وارد `challenge_markets` نمی‌شود. به‌روزرسانی جدول اتمی است. اگر پاسخ محدودیت‌ها ناقص باشد اسکریپت متوقف می‌شود و همهٔ بازارها را مجاز فرض نمی‌کند. آخرین اسنپ‌شات موفق با زمانش باقی می‌ماند؛ شکست refresh به معنی معتبر بودن مجوزهای قبلی برای معامله نیست.

شناسهٔ حساب فقط در `.env` محلی ذخیره می‌شود. `WALLEX_PACKAGE_ID`، `MARKET_DATA_SYMBOLS` و `TRADING_ALLOWED_SYMBOLS` هم از کشف API به‌روز شده‌اند؛ کلیدها تغییر نکرده‌اند. تنظیم `TRADING_QUOTE_ASSET=TMN` فعلی، سیاست موتور آینده است و فهرست قابلیت طرح شامل جفت‌های تتری را حذف نمی‌کند. موتور آینده باید محدودیت quote را هم جداگانه اعمال کند و خروج نهایی چالش به تومان باشد.

**محدودیت تأیید:** ارتباط حساب و طرح با نام دقیق تطبیق یافته است؛ endpoint طرح فعال اجازهٔ دسترسی نداده است. این بررسی مجوز ثبت سفارش، اتصال قطعی کلید به حساب چالش، یا نبودن محدودیت اضافهٔ برگزارکننده را ثابت نمی‌کند. قبل از معامله باید این تطبیق و هر فهرست محدودکنندهٔ جداگانه تأیید شود. موتور معامله همچنان غیرفعال است.

منابع رسمی: [حساب‌های اعتباری](https://developers.wallex.ir/docs/trade-credit-active-sub-account-list)، [جزئیات طرح](https://developers.wallex.ir/docs/trade-credit-package-details)، [بازارها](https://developers.wallex.ir/docs/basic-services-markets).

## مخزن فعلی در SQLite

- `challenge_markets`: فقط ۱۲۰ بازار باقی‌مانده، نام، جفت ارز، دقت قیمت/مقدار و اسنپ‌شات قیمت و تغییر ۲۴ساعته.
- `market_catalog_sync`: زمان واکشی، طرح و روش تطبیق و هشدار تأیید حساب.
- `data/market-whitelist.json`: خروجی محلی کامل همان فهرست؛ در Git نیست.
- `GET /api/markets`: فهرست ذخیره‌شده برای پنل؛ بدون کلید یا اطلاعات مالی حساب.

تب بازارها فقط همین جدول را با جست‌وجو و فیلتر تومانی/تتری نشان می‌دهد. دکمهٔ بازخوانی، دیتابیس محلی را می‌خواند؛ برای تازه‌سازی از صرافی از فرمان بالا استفاده کنید. قیمت‌ها زنده نیستند و زمان اسنپ‌شات نمایش داده می‌شود. تاریخچهٔ کندل هنوز انبوه وارد نشده است.

در تعدادی از بازارهای پاسخ API قیمت صفر دیده شد. صفر را قیمت قابل معامله فرض نکرده‌ایم؛ پنل «قیمت معتبر موجود نیست» نشان می‌دهد. قرار داشتن در فهرست طرح به معنی وجود نقدشوندگی، قیمت معتبر یا امکان اجرای فوری سفارش نیست.

## منبع دادهٔ پیشنهادی

| منبع | کاربرد | تصمیم |
|---|---|---|
| API رسمی کندل والکس | OHLCV دقیقاً در بازار محل اجرای معاملات؛ شامل جفت‌های تومانی | منبع اصلی، با ممیزی کیفیت و پوشش |
| وب‌سوکت عمومی والکس V2 همراه REST عمق بازار | جمع‌آوری معاملات و عمق بازار از زمان شروع ضبط | مرحلهٔ بعد؛ منبع دادهٔ اجرای زنده و تست سایه |
| Binance Public Data | آرشیو فایل‌های روزانه/ماهانه و checksum برای بعضی جفت‌های مشترک | مکمل پژوهش؛ جایگزین قیمت، حجم، spread یا اجرای والکس نیست |

منابع: [کندل والکس](https://developers.wallex.ir/docs/basic-services-candles)، [وب‌سوکت والکس](https://developers.wallex.ir/docs/socket-intro)، [آرشیو رسمی Binance](https://github.com/binance/binance-public-data).

اگر دادهٔ مکمل Binance اضافه شود، فقط برای نمادهای مشترک whitelist و با تأیید هویت دارایی است؛ رکوردها باید `source` مجزا داشته باشند. دادهٔ BTCUSDT بایننس را نباید BTCTMN والکس نام‌گذاری کرد. Binance برای جفت‌های تومانی این پروژه منبع مستقیم ندارد. در آرشیو اسپات Binance، timestamp از ابتدای ۲۰۲۵ به میکروثانیه است؛ والکس تاریخچه را با timestamp ثانیه‌ای مستند کرده است.

## نتیجهٔ نمونه‌خوانی واقعی تاریخچه

روی `BTCTMN`، endpoint رسمی `/v1/udf/history` با پارامترهای `symbol`, `resolution`, `from`, `to` بررسی شد:

- درخواست یک روز با `resolution=15`: ۱۴۴۰ ردیف با فاصلهٔ مشاهده‌شدهٔ ۶۰ ثانیه؛ این پاسخ را نباید ۱۵دقیقه‌ای برچسب زد.
- درخواست ۳۰ روز با همان رزولوشن: ۲۷۳۴۵ ردیف، شروع پاسخ حدود ۳ اکتبر و پایان ۲۲ اکتبر ۲۰۲۶؛ یعنی کل بازهٔ درخواستی برنگشت. این یک مشاهده است، نه ادعای سقف نگهداری ثابت صرافی.
- نمونهٔ یک‌ساعته با resolutionهای 1 و 15، هر دو ۵۹ ردیف با فاصلهٔ ۶۰ ثانیه برگرداند؛ resolution=60 در همان بازه یک ردیف داشت.
- طول آرایه‌های OHLCV در نمونه‌ها با آرایهٔ زمان برابر بود. این بررسی به معنی تضمین نبود gap، صحت اقتصادی تمام قیمت‌ها یا پوشش تمام ۱۲۰ بازار نیست.

بنابراین برای واردکنندهٔ آینده باید timeframe از اختلاف زمان‌های واقعی اعتبارسنجی شود؛ در صورت دریافت دادهٔ یک‌دقیقه‌ای، تجمیع ۱۵دقیقه‌ای باید محلی و با قواعد روشن انجام شود. بازه‌های ناقص با دادهٔ ساختگی یا کندل پرشدهٔ بی‌علامت پنهان نشوند.

کلید یکتای مناسب تاریخچه: `(source, symbol, interval_seconds, open_time)`؛ قیمت و مقدار به‌صورت decimal string، زمان UTC، زمان واکشی و نتیجهٔ ممیزی جدا ثبت شوند. کندل باز از مجموعهٔ بک‌تست حذف شود. درج تاریخچه فقط پس از بررسی عضویت نماد در whitelist تازه، بدون fallback به کل بازار انجام شود.
