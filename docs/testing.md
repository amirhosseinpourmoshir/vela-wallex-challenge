# تست و اعتبارسنجی

پیش‌نیاز Node.js 24.18+ و `npm ci`.

```powershell
npm test
npm run check
npm run build
```

`npm test` تمام فایل‌های تست config و services را اجرا می‌کند. این مجموعه از fetch و صرافی/مدل جعلی و SQLite حافظه‌ای استفاده می‌کند؛ کلید و سفارش واقعی لازم ندارد. تست‌های سرویس با دکمهٔ «تست سرویس» در پنل متفاوت‌اند؛ دکمهٔ تست مدل می‌تواند شبکه و هزینهٔ واقعی داشته باشد.

## مجموعه‌ها

| فرمان | پوشش |
| --- | --- |
| test:config | قالب، URL، سقف‌ها و کلیدهای قدیمی |
| test:services | metadata، حذف دادهٔ حساس و پاسخ سرویس با mock |
| test:markets | فهرست طرح، بازار، precision و محدودسازی |
| test:knowledge | تاریخچه، شکاف، دادهٔ تکراری و embedding جعلی |
| test:agent | برش زمانی، بک‌تست، هزینه، fill، توقف و stream |
| test:live | اختیار جلسه، local zero-call، ranking، MARKET/LIMIT، TTL، تطبیق و حفاظت |

تست‌های اصلی local و سفارش بررسی می‌کنند: هیچ فراخوانی LLM در مسیر محلی؛ رد درخواست تغییر موتور ذخیره‌شده؛ عدم سفارش از تنظیم ناقص؛ رد فروش بدون موجودی؛ عدم retry ارسال مبهم؛ اجرای جزئی و لغو باقیمانده؛ نگهداری حدود حساب؛ و تبدیل MARKET نامجاز قبل از ارسال.

## CI

workflow در `.github/workflows/ci.yml` روی push و PR، Node 24.18، npm ci، تست، بررسی TypeScript و build را اجرا می‌کند. secret صرافی/مدل نباید به این workflow اضافه شود. نتیجهٔ CI را از GitHub بخوانید؛ پاس‌شدن محلی اثبات پاس‌شدن runner دیگر نیست.

## حدود شواهد

پاس‌شدن تست‌ها اثبات سودآوری، صحت پیش‌بینی، صف واقعی سفارش یا نبود همهٔ خطاهای شبکه نیست. آزمون رفتاری با mock را از تست سایه، کاغذی و حساب صرافی تفکیک کنید. تغییر الگوریتم باید با سناریوهای زمانی مستقل ارزیابی شود؛ هدف‌گذاری سود برای مجبورکردن نتیجهٔ تست مناسب نیست.

برای تغییر مستندات، لینک محلی، نام فرمان‌ها، فیلدها و وضعیت فعلی را بررسی کنید. مستندات نباید از یک snapshot خصوصی، عملکرد تضمینی یا مجوز عمومی استنتاج کنند.
